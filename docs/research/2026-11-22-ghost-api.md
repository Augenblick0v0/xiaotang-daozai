# Ghost Downloader 3 真实进度与速度数据源调研

- 调研日期：2026-11-22
- 目标程序：`D:\Ghost Downloader\Ghost-Downloader-3.exe`，版本 4.5.11.0（pid 52156 运行时核对）
- 源码基线：tag **v4.5.11** = `a2fa591f71b74bf83b91dde4dceac09c5feaaa53`（2026-11-20），对照 main = `e59c67a34fccc89bb7ca810dc3d1186a2f236393`（2026-11-22）
- 本机数据目录：`C:\Users\Microsoft\AppData\Local\GhostDownloader`
- 结论：**能拿到真实进度与实时速度**，通道是浏览器扩展 WebSocket（`ws://127.0.0.1:14370`），不是 HTTP API，也不是 `tasks.jsonl`。

## 一、结论摘要

1. **真实进度和速度走浏览器扩展 WebSocket。** 端口 `Browser.Port`（默认 14370，只绑 `127.0.0.1` 和 `::1`），协议版本 2。用 `UserConfig.json` 里的 `Browser.BrowserExtensionPairToken` 发 `hello`，再发 `subscribe_tasks`，服务端推 `task_snapshot`。每条任务含 `progress`（0~100，保留 2 位）、`speed`（bytes/s）、`receivedBytes`、`fileSize`、`status`、`taskId`、`name`、`packName`。已在本机 pid 52156 上实测连通并收到 22 条任务。
2. **`tasks.jsonl` 不能当进度源。** `TaskStore.flush()` 只由任务事件（新增、暂停、删除、完成、失败等）触发，0.2 s 防抖；进度 tick 不触发落盘。所以下载中 `steps[].progress / receivedBytes / speed` 长期是事件时刻的旧值（新任务就是 0），完成瞬间才跳到 100，与实测一致。
3. **aria2 JSON-RPC（16800）是兼容桩，拿不到进度。** 只实现了 `aria2.getVersion`、`aria2.getGlobalOption`、`aria2.addUri` 三个方法，没有 `tellStatus / tellActive / tellWaiting`。实测 `aria2.tellStatus` 返回 `No such method`。而且它默认关闭。
4. **WebSocket 唯一缺的是保存路径。** `toTaskSummary()` 不返回 `outputFolder` / `outputPath`。用 `taskId` 去 `tasks.jsonl` join 一次即可补上（任务新增后 0.2 s 内落盘），join 成本很低。
5. **速度字段有 pack 差异。** http / ftp / bt / ed2k / m3u8 / zip 的 `step.speed` 有值；**bili 与 ffmpeg 的 `step.speed` 恒为 0**，ffmpeg 的 `receivedBytes` 甚至可能为 0（实测一条 34.7 MB 的 ffmpeg 任务完成时 `receivedBytes=0`）。Rust 侧要按 `packName` 决定是否用 `receivedBytes` 差分兜底，兜不出来就显示"未知"，不能显示 0 B/s。

## 二、通道 A：浏览器扩展 WebSocket（推荐，唯一实时通道）

### A.1 触发条件

- 设置项 `Browser.EnableBrowserExtension`，默认 `True`（`app/config/cfg.py:269`）。本机为 `true`。
- 监听地址：`127.0.0.1:<Browser.Port>`，端口默认 14370（`app/config/cfg.py:272`）。绑定成功后还会尝试同端口 `::1`（`app/services/port_listener.py:174-177`），所以 IPv6 本机也能连。
- `Browser.AutoSelectPort` 默认 `True`（`app/config/cfg.py:271`）。端口被占用时按候选列表 `14370, 24370, 34370, 44370, 38370` 依次尝试（`app/services/browser_service.py:93`、`app/engine.py:44-58`），成功后把实际端口**写回** `UserConfig.json` 的 `Browser.Port`（`app/services/port_listener.py:135-145`）。
- 鉴权：`Browser.BrowserExtensionPairToken`。为空时启动阶段自动生成 `token_urlsafe(16)` 并写入配置（`app/services/browser_service.py:199-200`）。本机已有值，长度 22。
- 不需要用户在 GUI 里点"配对"。`pair_request` 只是浏览器扩展首次拿 token 的路径，已有 token 直接 `hello` 即可（本次实测即如此）。
- 端口只绑 loopback，不对外网开放。

### A.2 握手流程

```
TCP/WS 连接 ws://127.0.0.1:14370/      （路径任意，服务端不校验）
  -> {"type":"hello","protocolVersion":2,"token":"<BrowserExtensionPairToken>","clientKind":"daozai","extensionVersion":"1.0.0"}
  <- {"type":"hello_ack","protocolVersion":2,"appVersion":"4.5.11","capabilities":{"taskSnapshots":true,"taskActions":[...]}}
  -> {"type":"subscribe_tasks"}
  <- {"type":"task_snapshot","tasks":[ ... ]}
```

- `hello` 与 `pair_request` 是仅有的两个免认证消息；其余未认证会回 `{"type":"error","code":"unauthorized"}` 并断开（`app/services/browser_service.py:357-399`）。
- `protocolVersion` 必须严格等于 2，否则回 `protocol_mismatch` 并断开（`app/services/browser_service.py:418-421`）。
- `token` 必须严格等于配置值，否则 `unauthorized` 并断开（`app/services/browser_service.py:422-426`）。
- `extensionVersion`、`installType` 都可缺省。**不要填 `installType="development"`**：当它等于 development 且 `extensionVersion` 高于 2.3.4 时，服务端会触发扩展重装并下发 `reload`（`app/services/browser_service.py:447-456`）。
- `hello_ack.capabilities.taskActions` 当前为 `["toggle_pause","cancel","remove","redownload","open_file","open_folder"]`（实测 + `app/services/browser_service.py:49-76`）。

### A.4 可直接粘贴的验证脚本（已在本机实测通过）

PowerShell 7（Windows 自带 `pwsh` 即可，无需装任何东西）：

```powershell
$cfg   = Get-Content "$env:LOCALAPPDATA\GhostDownloader\UserConfig.json" -Raw | ConvertFrom-Json
$port  = $cfg.Browser.Port
$token = $cfg.Browser.BrowserExtensionPairToken

$ws = [System.Net.WebSockets.ClientWebSocket]::new()
$ct = [System.Threading.CancellationToken]::None
$ws.ConnectAsync([Uri]"ws://127.0.0.1:$port/", $ct).Wait(5000) | Out-Null

function SendJson($o) {
  $b = [Text.Encoding]::UTF8.GetBytes(($o | ConvertTo-Json -Compress))
  $ws.SendAsync([ArraySegment[byte]]::new($b), 'Text', $true, $ct).Wait(5000) | Out-Null
}
function RecvText {
  $buf = New-Object byte[] 1048576
  $t = $ws.ReceiveAsync([ArraySegment[byte]]::new($buf), $ct)
  if (-not $t.Wait(5000)) { return $null }
  [Text.Encoding]::UTF8.GetString($buf, 0, $t.Result.Count)
}

SendJson @{ type='hello'; protocolVersion=2; token=$token; clientKind='daozai' }
$ack = RecvText
SendJson @{ type='subscribe_tasks' }
$snap = RecvText
($snap | ConvertFrom-Json).tasks |
  Select-Object taskId,name,status,progress,receivedBytes,fileSize,speed,packName |
  Format-Table -AutoSize
$ws.Dispose()
```

### A.5 刷新频率

- 进度源：各 pack 的 `_supervise()` 每秒重算一次 `progress / receivedBytes / speed`（HTTP：`features/http_pack/task.py:267-298`，`await asyncio.sleep(1)` 在 293 行）。
- 推送源：全局 `SpeedMeter` 每秒 `speedChanged.emit()`（`app/services/speed_meter.py:47-57`），`BrowserService` 把它和 11 个任务事件一起接到 `_onTasksChanged`（`app/services/browser_service.py:199-205`），后者合并后调 `_sendSnapshots()`（`334-338`）。
- 因此**下载中约 1 Hz 推送全量快照**，最大延迟约 1 s（`_isSnapshotPending` 合并同一轮内多次变更）。
- **空闲时不推送**：没有 running / seeding 任务时 `SpeedMeter.stop()`（`app/services/task_service.py:658-662`），没有 tick；同时 `lastSnapshot` 内容去重（`browser_service.py:352-354`），相同快照不发。实测空闲监听 8 s 只收到 2 帧（`hello_ack` + 首帧快照），之后静默。
- **强制刷新**：重发一次 `{"type":"subscribe_tasks"}`，服务端会 `lastSnapshot=None` 并立即再发一帧（`browser_service.py:392-395`）。可以拿它当低频心跳/看门狗。
- 运行态 1 Hz 这一点是**代码推得**，本机当时没有进行中的任务，未做运行态实测（见"未验证"清单）。

## 四、通道 C：`tasks.jsonl`（元数据 + 保存路径，无实时进度）

### C.1 位置与写入方式

- 路径：`%LOCALAPPDATA%\GhostDownloader\tasks.jsonl`，即 `APP_DATA_DIR / "tasks.jsonl"`（`app/config/paths.py:22-28`、`app/services/task_service.py:55-59`）。
- 写入：**全量重写**。遍历内存中所有任务，`json.dumps(task.toDict())` 逐行写 `tasks.jsonl.tmp`，再 `Path.replace()` 原子替换（`app/services/task_service.py:178-196`）。
- 触发：只有任务事件。`_flushSoon()` 做 0.2 s 防抖（`task_service.py:557-565`），调用点在 add(369)、pause(418)、delete(435)、redownload(445)、edit(459)、setCategory(465)、updateSelection(485)、run 结束(666)、run 失败(678) 等；退出时 62/67 行同步 `flush()`。
- **进度 / speed 更新路径不调用 flush**。所以运行中文件里的进度是"最后一次任务事件时"的快照。

### C.2 字段

任务级（实测样本）：

```json
{"name":"NikonLink-v0.3.18-arm64.apk","url":"https://...","packId":"http","taskId":"tsk_e550...",
 "status":"COMPLETED","steps":[...],"createdAt":1795284000,"completedAt":1795284010,

```

step 级：`stepIndex, fileIndex, stepId, status, progress, receivedBytes, speed, url, fileSize, headers, clientProfile, userAgent, subworkerCount, canUseRangeRequests, httpByteOffset, lastModified, filePath, isAccelerated, type`。

### C.3 用途与局限

- **用途**：按 `taskId` join，补 `outputFolder`（再拼 `name` 得保存路径）、`url`、`fileSize`、`completedAt`。这是目前唯一稳定的保存路径来源。
- **局限**：运行中 `progress` / `receivedBytes` / `speed` 是旧值；新任务刚建时全是 0。**不能拿它画进度条。**
- 实测：02:06 时 68633 B、23 条任务，全部 `COMPLETED`；另一 agent 的探针任务 `ghostprobe-20261122-022522.bin`（`fileSize=419430400`）完成时 `receivedBytes=393300224`，差 26 MB，进一步说明 `receivedBytes` 不能当进度真值。

## 五、通道 D：`.ghd` 分片记录文件（离线兜底，仅 HTTP/FTP）

- 路径：输出文件全路径 + `.ghd`（`app/models/task.py:279-281`；HTTP 侧 `features/http_pack/task.py:149-150`）。
- 内容：每个 subworker 24 字节，小端 `<QQQ>`，依次是 `start, position, end`（`features/http_pack/task.py:152-166` 读取，`274-282` 写入）。文件长度 = 24 × subworkerCount。
- 刷新：`_supervise()` 每秒 `seek(0)` + `write` + `flush` + `truncate`（`features/http_pack/task.py:274-282`），**这一步是每秒真落盘的**。
- 已完成字节：`Σ(position_i - start_i)`（`_loadRecord` 里 `receivedBytes = position - start`，`152-166`）。
- 生命周期：任务完成时删除（`features/http_pack/task.py:501/543/562` 调 `_deleteRecord`）。所以它只在下载中存在。
- 适用：`canUseRangeRequests` 为 true 的 HTTP/FTP 多线程任务；BT、m3u8、ffmpeg、zip 没有这种记录。
- 局限：没有文件名、总大小、状态、速度；只能算"已完成字节"。且需要先知道输出文件路径（从 `tasks.jsonl` 的 `outputFolder + name` 拼）。
- 实测：当前 `D:\下载` 下没有 `*.ghd`（所有任务都已完成并清理），运行态样本未采集。

**定位：WS 关闭或连不上时的最后兜底，只能画一个字节级进度，不能单独作为数据源。**

```python
def currentSnapshot(self) -> tuple[float, int, int]:
    selectedIndexes = self.selectedIndexes
    steps = [s for s in self.steps if self.isStepSelected(s, selectedIndexes)]
    if not steps:
        return 0.0, 0, 0
    progress = 0.0
    speed = 0
    receivedBytes = 0
    for step in steps:
        progress += step.progress
        speed += step.speed
        receivedBytes += step.receivedBytes
    return progress / len(steps), speed, receivedBytes
```

## 九、风险与限制

1. **协议版本硬编码。** 服务端只接受 `protocolVersion == 2`（`browser_service.py:418-421`）。Ghost 升级后若变 3，连接会被 `protocol_mismatch` 断开。Rust 侧要把它当"不可用"而不是"0 个任务"。
2. **token 会轮换。** 用户在设置页点"重新生成令牌"会重设 token 并踢掉所有已认证会话（`browser_service.py:229-238`）。重连时必须重新读 `UserConfig.json`，不能缓存一辈子。
3. **端口会漂移。** `AutoSelectPort=True` 时 14370 被占用会换到 24370/34370/44370/38370，并写回配置（`port_listener.py:135-145`）。不要硬编码 14370；先读配置，再按候选列表重试。
4. **快照是全量的。** 每次约 7 KB（实测 22 条任务 7061 B）。任务几百条时每帧几十 KB、1 Hz，解析要放在单独 task，不要阻塞 UI。
5. **没有保存路径。** 只能 join `tasks.jsonl`。join 时注意：任务刚建时 jsonl 可能还没落盘（0.2 s 防抖）。
6. **`receivedBytes` 不可靠。** ffmpeg 任务恒 0；HTTP 完成瞬间也可能小于 `fileSize`（探针任务 393300224 vs 419430400）。不要用它算百分比，百分比只信 `progress`。
7. **`speed` 有 0 值 pack。** bili、ffmpeg 不写 `step.speed`；BT 在首个 libtorrent 回调前也是 0。按 `packName` 区分处理。
8. **多 step 是算术平均。** 多文件任务里小文件和大文件权重相同，和"总字节进度"不一致（`task.py:367-374`）。岛仔如果要字节级总进度，得自己在 step 层加权（快照不提供 step 明细，只能接受平均值）。
9. **空闲无推送。** 不能用"收不到帧"判断 Ghost 挂了。需要独立的存活探测（见 A.5 的 `curl` 426 或重发 subscribe）。
10. **无应用层心跳。** `websocket_stream.py:37-59` 只把 TEXT/BINARY 交给上层，PING/PONG 不暴露；半开连接只能靠客户端 ping 或读超时发现（服务端是否自动回 pong 未验证）。
11. **`installType` 有副作用。** 见 A.2，别填 development。
12. **本机安全面。** token 明文存在 `UserConfig.json`，本机任意进程可读；WS 是明文 loopback。aria2 端口若像本机这样 `Token=""`，本机任意进程都能 `addUri` 塞任务。这是 Ghost 的设计，不是岛仔能修的，但值得在集成文档里注明。
13. **权限差异未验证。** 若 Ghost 以管理员身份运行、岛仔以普通用户运行，读 `UserConfig.json` 与连 loopback 一般仍可行，但未实测。

## 十、给 Rust（岛仔）的接入建议

### 10.1 数据源优先级

```
1) 浏览器扩展 WS（实时 progress / speed / status）
2) tasks.jsonl（taskId -> outputFolder + name + fileSize，补路径；离线状态快照）
3) .ghd（仅 WS 不可用且任务是 HTTP/FTP 时，算已完成字节）
4) 都不可用 -> UI 显示"Ghost 未连接"，不要显示 0%
```

### 10.2 连接与重连

- 读 `%LOCALAPPDATA%\GhostDownloader\UserConfig.json` -> `Browser.Port` / `Browser.BrowserExtensionPairToken` / `Browser.EnableBrowserExtension`。
- 依次尝试 `127.0.0.1:<port>`，失败再 `[::1]:<port>`，再候选端口列表。
- 重连退避：2.5 s -> 5 s -> 10 s -> 30 s 封顶（浏览器扩展自己就是 2500 ms 固定重连，`desktop-bridge.ts:125-133`，可参考）。
- 每次重连都重读配置（token / 端口可能已变）。
- 连接成功后：`hello` -> 等 `hello_ack` -> `subscribe_tasks`。`hello_ack.protocolVersion != 2` 视为不兼容，停止重试并提示升级。

### 10.3 心跳与轮询

- 正常态：纯事件驱动，1 Hz 推送，不需要轮询。
- 看门狗：若 3 s 没收到任何帧，且 `tasks.jsonl` 里存在 `RUNNING` 任务 -> 重发 `subscribe_tasks`（服务端会立即回一帧，`browser_service.py:392-395`）。
- 低频保活：每 15~30 s 重发一次 `subscribe_tasks`，兼作"服务端还活着"的探测；帧很小，代价可接受。
- 进程存活探测（可选）：`curl http://127.0.0.1:<port>/` 返回 `426 Upgrade Required` 即端口在监听（本机实测）。

### 10.4 字段映射（Rust struct）


### 10.5 速度兜底

```
if speed > 0: 用 speed
else if packName in {http, ftp, bt, ed2k, m3u8, zip} and receivedBytes 在涨:
    speed = (receivedBytes_now - receivedBytes_prev) / dt   // 2~3 s 窗口，做 EMA 平滑

```

ffmpeg / bili 任务直接用 `speed=None`；ffmpeg 的 `receivedBytes` 也不能用于差分。

### 10.6 路径 join

- 维护 `HashMap<taskId, TaskMeta { output_folder, name, file_size, url }>`。
- 触发刷新：收到新 `taskId`、任务变为 `completed`、每 30 s、或 `tasks.jsonl` 的 mtime 变化。
- 解析时按行 `serde_json::from_str::<Value>`，只取需要的键，别把整个文件反序列化成强类型（字段会随版本变）。
- 拼路径：`Path::new(outputFolder).join(name)`。**注意 `name` 可能含 Windows 非法字符已被 Ghost 清洗过**，直接拼即可。

### 10.7 建议的轮询间隔总结

| 数据 | 间隔 | 说明 |
|---|---|---|
| WS 快照 | 事件驱动（约 1 s） | 不要额外轮询 |
| `subscribe_tasks` 看门狗 | 3 s 无帧时一次 | 仅在存在 running 任务时 |
| 保活 subscribe | 15~30 s | 兼作存活探测 |
| `tasks.jsonl` | 30 s 或 mtime 变化 | 只取路径/元数据 |
| `.ghd` | 1 s | 仅 WS 不可用且 HTTP/FTP 任务 |

### 10.8 Rust 最小客户端骨架

```rust
use futures_util::{SinkExt, StreamExt};
use serde::Deserialize;
use serde_json::json;
use tokio_tungstenite::tungstenite::Message;

#[derive(Debug, Deserialize)]
#[serde(tag = "type")]
enum ServerMsg {
    #[serde(rename = "hello_ack")]
    HelloAck {
        #[serde(rename = "protocolVersion")] protocol_version: u32,
        #[serde(rename = "appVersion")] app_version: String,
    },
    #[serde(rename = "task_snapshot")]
    TaskSnapshot { tasks: Vec<TaskSummary> },
    #[serde(rename = "error")]
    Error { code: String, message: String },
    #[serde(other)]
    Other,
}

pub async fn run(port: u16, token: String) -> anyhow::Result<()> {
    let (mut ws, _) = tokio_tungstenite::connect_async(
        format!("ws://127.0.0.1:{port}/"),
    ).await?;

    ws.send(Message::Text(json!({
        "type": "hello",
        "protocolVersion": 2,
        "token": token,
        "clientKind": "daozai",
        "extensionVersion": "1.0.0"
    }).to_string().into())).await?;

    ws.send(Message::Text(json!({"type": "subscribe_tasks"}).to_string().into())).await?;

    let mut keepalive = tokio::time::interval(std::time::Duration::from_secs(20));
    loop {
        tokio::select! {
            msg = ws.next() => match msg {
                Some(Ok(Message::Text(t))) => match serde_json::from_str::<ServerMsg>(&t) {
                    Ok(ServerMsg::TaskSnapshot { tasks }) => { /* 推给 UI */ }
                    Ok(ServerMsg::HelloAck { protocol_version, .. }) if protocol_version != 2 => {
                        anyhow::bail!("ghost protocol mismatch");
                    }
                    Ok(ServerMsg::Error { code, message }) => {
                        anyhow::bail!("ghost error {code}: {message}");
                    }
                    _ => {}
                },
                Some(Ok(_)) => {}
                Some(Err(e)) => return Err(e.into()),
                None => anyhow::bail!("ghost ws closed"),
            },
            _ = keepalive.tick() => {
                ws.send(Message::Text(json!({"type":"subscribe_tasks"}).to_string().into())).await?;
            }
        }
    }
}
```

依赖：`tokio`（`rt-multi-thread`, `macros`, `time`）、`tokio-tungstenite`、`futures-util`、`serde`（`derive`）、`serde_json`、`anyhow`。

### 10.9 关于"零新依赖"

如果岛仔不想引入 `tokio-tungstenite`，要注意：**这条通道不是 HTTP GET，不能靠 `TcpStream` 发一个 GET 就读到 JSON**。`curl http://127.0.0.1:14370/` 只会得到 `426 Upgrade Required`，没有任何任务数据（本机实测）。

要零依赖接实时数据，只能自己实现 RFC 6455 的最小客户端，工作量约 150~250 行：

1. TCP 连 `127.0.0.1:<port>`，发 Upgrade 请求，必须带 `Connection: Upgrade`、`Upgrade: websocket`、`Sec-WebSocket-Version: 13`、`Sec-WebSocket-Key: <16 字节 base64>`。
2. 读 101 响应，校验 `Sec-WebSocket-Accept`（可选但建议）。
3. 发送帧必须加掩码（客户端要求），解析服务端帧不需要掩码；需要处理 126/127 扩展长度、FIN=0 的分片拼接、`opcode=0x8` 关闭、`0x9` ping（回 pong）。
4. 文本帧载荷就是上面的 JSON。

如果嫌麻烦，退而求其次：只用 `tasks.jsonl` + `.ghd`（仅 HTTP/FTP、无速度），体验会明显差一档。建议还是加一个成熟的 WS 依赖。

## 十二、一句话给岛仔

接 `ws://127.0.0.1:<Browser.Port>`，用 `BrowserExtensionPairToken` 发 `hello`（protocolVersion=2），再 `subscribe_tasks`；快照里的 `progress` 和 `speed` 就是真实值，`taskId` 去 `tasks.jsonl` 换 `outputFolder` 拼保存路径；`speed==0` 时按 `packName` 决定是否用 `receivedBytes` 差分兜底；`tasks.jsonl` 永远不要拿来画进度条。
